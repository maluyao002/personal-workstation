# 个人工作站需求文档

日期：2026-10-11　更新：2026-10-13
状态：第一版需求已确认；已进入工程路线图规划，尚未开始应用开发

个人工作站是整合个人工作、学习、家庭事务、新闻和投资信息的私人站点。它通过每日简报、日内跟踪和随时交互，帮助用户理解值得关注的变化、组织项目与待办，并在确认后执行邮件和日程操作。

本文确定产品方向、第一版范围和难以事后改变的基础边界，不规定技术栈、数据库、界面布局或开发计划。第 1–9 节为已确认的第一版要求，包括全部质量标准与验收场景，以及本次补充的日计划、邮件处理、数据来源、金融覆盖、新闻变化和运行状态规则；第 10 节列出实施前需要验证或配置的事项，需求确认不代表这些接入能力已经验证。

## 1 产品定位与使用者

第一版仅供用户本人使用。个人工作不涉及公司账户：Gmail 和 Google Calendar 使用同一个个人 Google 账户，家庭日程也使用 Google Calendar。

各功能之间可以在授权范围内关联，例如新闻关联持仓、邮件形成任务、工作与家庭日程共同参与时间安排。工作站统一管理待办，邮件和日历仍由原有服务保存并同步；用户可以在工作站内确认并执行相关操作。

未来允许家人独立登录，共享指定日程和任务。因此从一开始需要区分内容所属用户、所属领域和共享范围。个人邮件与财务信息默认不向家人共享，需要单独授权。第一版不要求实现家庭多人协作界面。

## 2 第一版范围

| 能力 | 第一版要求 |
| --- | --- |
| 每日简报 | 汇总邮件、日程、待办、重点新闻和投资动态 |
| 随时交互 | 可从具体事项继续追问、深入分析或发起任务，承接相关上下文 |
| 项目与待办 | 管理工作项目、学习课程、家庭事务及零散待办，支持拆分任务和跟踪进度 |
| 邮件与日历 | 接入个人 Gmail 和 Google Calendar，支持经确认后的相关操作 |
| 新闻与研究 | 关注 AI、科技、宏观经济、地缘政治、金融市场、持仓及关注标的 |
| 投资账户 | 希望接入 Robinhood、Charles Schwab 的普通投资账户和退休账户，仅只读 |
| 金融分析 | 持仓汇总、收益和资产分布、风险分析，以及结合个人情况的配置与再平衡建议 |
| 长期记忆 | 根据对话和使用习惯提出建议，经确认后保存，支持查看、修改和删除 |
| 使用设备 | 电脑端完整使用，手机端辅助查看、确认和追问，支持外出访问 |

银行账户接入暂缓。需要综合现金、负债、资金需求等情况时，可由用户补充，分析应明确实际覆盖的数据范围。

美股个股、大宗商品等关注标的的研究属于第一版，侧重事实、驱动因素和风险。第一版不提供具体标的的买入、持有、减仓指令式建议；未来可再讨论扩展。资产配置和再平衡建议保留，但不执行交易。

## 3 日常使用流程

### 每日简报与日内跟踪

每天生成一份覆盖各领域的简报。用户可以查看摘要，按需深入分析，也可以从简报中的邮件、新闻或研究结果发起任务。

周中日内，在用户设定的跟踪时段，每 30–60 分钟检查持仓、关注标的及相关新闻，支持手动刷新。AI 和科技新闻每天汇总。任务和日程的提醒单独配置。

所有提醒只在工作站内展示，不发送邮件、系统通知或其他站外提醒。任务与日程、持仓及关注标的的重大变化在站内及时呈现；页面打开期间也能更新。后台跟踪不依赖页面是否打开。

显示数据时间、最近检查时间和更新失败状态。检查频率不等于数据源更新频率，不能把一次检查成功当作获得了新的市场或账户数据。

### 任务收集与安排

从邮件、新闻和分析结果中提取的事项，自动进入“待整理的任务收件箱”，保留来源。来源明确提供的截止时间应能回到对应依据；系统推测的截止时间只作为待确认建议，不能伪装成原文要求。为方便安排提出的“建议处理日期”与截止时间分开标示。用户采纳建议，也不改变原始来源实际说过什么。

由用户确认是否要做，以及属于哪个项目，再进入正式任务管理。工作站可以提出项目拆解和每日安排建议，不直接改动用户已确认的安排。新增事项或时间冲突需要调整安排时，先提出建议。

长期目标管理和定期复盘不纳入第一版。

### 邮件处理与任务去重

Gmail 的已读状态与工作站中的处理状态分别管理；读过邮件不等于已完成行动，等待他人回复也不等于任务已经完成。工作站优先呈现尚需判断或处理的邮件；筛选、重要性和行动判断均可纠正，已同步范围内被筛除或已处理的邮件仍可回看、恢复处理，不因筛选而删除原邮件。

同一封邮件或同一来源事项重复同步、分析或确认，不应生成重复任务。用户可以将候选事项采纳为新任务，或关联已有任务。邮件、所提议的事项和关联任务之间保留来源关系；同一线程中后续出现的新邮件必须重新判断，不能因先前邮件已处理就自动视为已处理，也不能因属于同一线程而忽略新的独立事项。

工作站内标记处理、纠正判断或关联任务，不自动改变 Gmail 的已读、归档或删除状态。发送邮件及其他已授权外部操作仍按具体操作确认。

### 第一版邮件与日历操作范围（已确认）

2026-10-12 已确认以下操作范围，所有外部修改均须展示具体对象与内容并由用户确认后执行：

| 领域 | 第一版支持 | 留在原工具处理 |
| --- | --- | --- |
| Gmail | 撰写、回复并确认发送；归档；标记已读/未读；添加或移除已有标签 | 转发、附件处理、批量处理、移入垃圾箱、永久删除、自动转发规则；创建/重命名/删除标签不在已有标签操作范围内 |
| Google Calendar | 在用户选定且有写权限的日历中创建、修改、取消无其他参与者的单次事件，涵盖工作、学习和家庭安排 | 邀请他人、回复会议邀请、重复事件及其单次例外的修改、修改日历共享权限等复杂操作 |

读取与执行分别判断：已获读取权限的会议、重复事件及其例外仍参与日程展示、占用和冲突分析，不因不允许修改而视为空闲；需要调整时提示在 Google Calendar 中处理。邮件附件内容不在工作站内处理，可回到 Gmail 查看。

操作预览明确收件人、正文，或目标日历、事件时间/时区及具体改动。写入共享日历可能让原服务中已有权限的人看到事件，需明确目标日历，不能将家庭日历等同于仅本人可见；工作站不因此新增共享权限。执行前再核对对象与权限是否变化，超出上述范围时不执行并提示使用原工具。

内部邮件处理状态与 Gmail 状态分开，确认日计划与批准日历写入分开；结果未知时先核对，不盲目重试。此范围是已确认的产品要求，不代表实际 OAuth 权限已授予或接口能力已验证。用户确认的邮件发送属于请求执行的外部操作，不改变“不发送站外主动提醒”的规则。

### 日计划的可行性

每日安排建议应结合当前日历占用、可用时间、任务优先级、截止时间和已知的预计耗时，展示明显的时间冲突与容量不足。用户提供的耗时与系统估计需能区分；没有估时或日历覆盖不全时，明确表示可行性尚未核实，不能把未知当作有空闲时间。

用户可以调整建议，也可以保留尚有冲突或信息不全的草案；只有相应依据足够且未发现冲突时，才可表述为已核对可行。用户确认采纳任务、确认日计划与同意写入 Google Calendar 是不同的决定，不能相互代替。

确认日计划前应核对所依赖的日历是否已变化或过期。若有变化，保留草案并说明需调整或复核的部分；之后新发现的冲突也只提出调整建议，不直接改动已确认安排。事件时间和时区应清楚可辨，全天事件对可用时间的影响不明时标为待核实。

## 4 新闻与金融分析

### 新闻范围与深度

| 主题 | 默认深度 | 深入分析条件 |
| --- | --- | --- |
| AI 和科技动态 | 较详细分析 | 可随时追问和继续研究 |
| 宏观经济 | 简要概览 | 涉及持仓、关注标的或重大变化 |
| 地缘政治，尤其是中美关系 | 简要概览 | 涉及持仓、关注标的或重大变化 |
| 金融市场 | 简要概览 | 涉及持仓、关注标的或重大变化 |
| 持仓与关注标的 | 展示相关动态与潜在影响 | 重要变化或用户主动发起分析 |

其他新闻主题暂不加入，后续可以调整。具体关键词、来源选择和“重大变化”的判断依据，在后续配置和验证中明确。

### 新闻去重与变化呈现

同一事件的重复报道合并呈现，保留各自的来源和时间，不因去重而丢失证据。转载或引用同一个原始来源，不算多个独立来源的证实；单一来源、来源冲突或已经失效的信息需明确标示。

日内更新应说明相对于上次成功更新的新增事实、修正、撤回或影响判断变化，区分“首次发现”与“刚刚发生”。已确认无新内容时，不用改写旧摘要制造更新；检查失败或覆盖不全时，不能声称没有变化。重要修正或撤回需要在后续展示的相关分析中可见，不能继续把旧结论呈现为有效事实。

### 系统研究判断与个人观点（已确认）

2026-10-12 已确认：系统判断自动更新，个人观点由用户确认后保存，重要分歧只在站内提示。系统判断与个人观点分别展示和保留版本，不合并为一个含义不明的“当前判断”。

在已授权的主题、数据、跟踪和费用范围内，AI 可根据新证据自动更新系统分析，无需逐次确认。每次实质更新说明依据、与上次的差异、不确定性和数据覆盖；来源或覆盖不足时明确局限，自动更新不等于结论已经核实或用户已经认可。

用户可以明确采纳某个系统判断版本、修改后保存，或单独记录不同观点。只有用户明确确认的内容才保存为个人观点，普通浏览、标记已读、追问和对话中的推测不算确认。尚无个人观点时仍能正常跟踪，不推断用户立场；AI 不覆盖已保存观点，也不因模型结论改变而替用户改变立场。

系统发现与已保存个人观点的重要分歧或挑战其关键依据的新证据时，在研究主题及相关站内提醒中说明分歧、证据和仍待验证的问题；不因措辞不同就视为重要分歧，不默认系统正确或用户错误。重复检查不反复提示同一分歧，查看提示不等于采纳或解决分歧。用户决定是否调整个人观点，系统仍可继续跟踪。

采纳研究观点不自动创建正式任务、修改已确认计划、执行邮件或日历操作、交易或转账，也不自动保存为跨主题长期记忆；这些行为继续遵守各自确认与授权规则。研究判断与个人观点均遵守第 6 节的保存、删除和权限边界。

### 账户与建议边界

希望读取 Robinhood 和 Charles Schwab 的普通投资账户与退休账户，实际可用的接入方式、账户类型和数据字段需要验证。接入目标不等于已确认能够完整同步。

在账户数据和用户补充信息的基础上，结合投资目标、投资期限、风险承受能力和资金需求，提供资产配置、集中度等风险分析以及再平衡建议。相关个人情况在使用时设置，不在本需求阶段要求披露。

金融账户始终只读，不自动交易或转账。新闻与持仓可以关联，分析结果可以形成待整理任务，但不能因此获得账户操作权限。

### 金融覆盖与计算依据

2026-10-12 已确认：第一版金融数据从接入时的当前账户状态及在已授权范围内可取得的历史开始，不以完整历史回填为启用或验收前提。按账户说明历史覆盖期间、成本记录及其他缺口；缺失历史不推算为真实记录，也不据此生成完整收益结论。已确认的历史保留期限从实际取得的数据适用，不意味着接入时必须补齐过去 5 年。

以用户选择纳入分析的券商和账户为预期覆盖范围，分别展示普通投资账户、退休账户、币种、持仓与现金的数据时间和缺失情况。未连接、同步失败、数据过期和覆盖未知要分别说明；不能因为读取失败就把预期账户从统计范围中悄悄移除。

合计金额、持仓比例及配置建议都需说明实际覆盖的账户与计算范围。仅取得部分数据时，可以展示已覆盖部分的结果，但必须标为部分结果，不能当作全部投资资产或完整家庭财务状况。持仓研究对象从有效账户持仓中获得，用户添加的关注标的是补充，不需要重复手填已有持仓。

账户总值增加不直接等于投资收益。展示收益或解释价值变化前，须核对相关历史、持仓数量、现金流、价格、币种和时间是否足以支持该结论；汇率、公司行动或快照时间差等因素无法排除时，应说明限制。缺少必要数据时，不生成看似完整的收益率、收益曲线或精确归因。

券商快照只能说明观察到的账户状况，不能单独证明市场变化的原因。原因分析应另有公司披露、行情或相关新闻等依据；证据不足或冲突时标为假设或未知。个性化配置建议仍保留，但需列明所用个人目标、数据范围和假设；资料不足以支持的结论暂不生成。上述规则是现有分析的正确性要求，不新增完整的多因素量化归因功能。

## 5 权限与领域关联

分别管理读取信息、跨领域分析、向云端 AI 发送数据、执行操作、向家庭成员共享内容的权限。获得其中一种授权，不自动获得其他权限。

| 场景 | 已确认边界 |
| --- | --- |
| 邮件发送、日历修改等外部操作 | 仅第 3 节已确认清单内的动作，用户对具体内容确认后执行 |
| 银行和证券账户 | 只读；银行第一版暂不接入 |
| 从信息中提取任务 | 可以自动放入待整理收件箱，正式采纳与项目归属由用户确认 |
| 已确认的每日安排 | 不自动修改 |
| 新闻与持仓关联 | 允许持续关联 |
| 工作与家庭日程统筹 | 允许持续关联 |
| 工作邮件正文跨领域使用 | 需要单独授权 |
| 其他跨领域使用 | 按领域另行授权，不默认全部互通 |
| 家庭成员查看个人邮件和财务信息 | 默认不共享，需单独授权 |
| 保存长期记忆 | 用户确认后保存 |
| 新增服务、升级或增加支出 | 用户确认后才能发生 |

领域关联授权一旦授予，持续有效，不要求每次分析都重复询问。执行邮件、日历操作的确认仍单独进行。

同一个 Google 账户同时包含工作和家庭内容，因此不能仅用账户区分领域。工作邮件正文的跨领域限制，不能因其来自个人账户而被忽略；领域划分方式需在接入前确定。

## 6 数据与长期记忆

### 数据来源与用户决定

区分外部来源记录、用户作出的决定和 AI 生成的解释：邮件、日历、券商记录及新闻原文提供对应事实；用户确认的任务、安排和个人资料代表用户决定；摘要、分类、推测和建议属于可纠正的解释。用户手工补充的财务信息需标为用户提供，不能冒充券商同步结果。

来源引用保留可识别的对象或链接、数据时间、最近成功同步时间以及当前可用性。本地摘要或缓存不能冒充原始来源。同一来源可以关联多个任务或项目，但重复获取不应制造重复事项；用户修改内部任务，不等于修改原邮件或原日程。

同步与新的 AI 建议不得覆盖用户已保存的任务状态、文字、项目归属和确认结果。来源修改、暂时不可访问、取消或授权撤销时，应更新来源状态并说明影响，保留用户自写内容；某条日历记录不在本次查询窗口内，不能据此判定它已取消。保留引用关系不代表允许继续使用已撤销授权的来源正文或派生内容，仍须遵守领域授权与撤销规则。

### 分层保存原则

2026-10-12 已确认采用按数据类型分层保存：研究判断与必要证据、邮件正文、金融历史、临时 AI 输入与运行记录分别制定保留策略，不统一全部长期保存或全部短期清理。具体数据范围和保留期限逐项讨论，尚未确认的期限不得自动作为清理或永久留存规则。分层保存不改变用户删除权、领域授权、云端处理限制或公开源码的隐私边界。

### 邮件正文保存（已确认）

2026-10-12 已确认采用按需读取、短期缓存：收到的邮件正文在本地最多缓存 24 小时，不建立长期正文镜像，也不纳入任何本地或云端备份。按需读取包含已授权的每日简报、任务提取与主动追问，不需要逐封重复确认；领域、云端处理及撤销规则继续生效。

## 8 AI 与费用原则

优先使用 Codex 作为 AI 后台，并尽量复用用户已有订阅。具体接入方式和订阅能力应经过验证，不把全部后台运行、外部数据或额外 API 费用视为已包含在订阅中。

2026-10-12 已确认采用 Codex 优先、AI 后台可替换的方向。工作站独立管理业务数据、研究历史、个人观点、已确认记忆、权限、操作确认和定时调度；这些内容不只保存在某个 AI 会话中。第一版只实际启用一个经过验证的 AI 后台，不同时接入多个后台，不增加多服务路由、自动故障切换或多模型协作平台。

预留更换 AI 后台的能力，未来替换时尽量保留已有数据和工作流程；不同后台的能力仍须重新验证，不承诺无需适配或效果完全相同。启用新服务、更换数据接收方或隐私条件，以及新增费用，都需用户确认；已有领域授权不自动授予新服务处理私人数据的权限。

AI 不可用时，在主机在线且应用正常运行的前提下，仍可查看已保存内容、管理内部项目与任务；定时调度由工作站管理，依赖 AI 的分析显示暂停或受阻状态。不依赖 AI 的同步可按现有权限和连接能力继续；不因 AI 故障扩大权限、增加支出或自动切换服务。

## 9 质量标准与验收场景

本节全部质量标准与验收场景已由用户确认，均纳入第一版范围，作为后续实施与验收的依据。

### 质量标准

1. **结论可追溯**：新闻和金融分析保留来源及时间，区分事实、推断和建议。来源存在分歧时说明分歧，不把缺失数据当作零值或无变化。
2. **操作可核对**：执行前展示具体对象和改动内容；执行后区分成功、失败和结果未知。重复点击、重试或恢复运行不能造成重复发送邮件或重复创建日历事件。
3. **权限可撤销**：用户可撤销连接和领域授权；撤销后停止相应读取与后续关联。由敏感信息生成的摘要、分析和记忆也继承相应限制，不能通过摘要绕过授权。
4. **私人访问**：外出访问也需要身份验证，私人数据不能通过公开链接直接访问。外部邮件、网页和新闻内容不能自行改变用户设定的权限或触发操作。
5. **中断不伪装为正常**：某个来源失败时，其他可用内容仍可展示，但明确缺失部分；恢复后更新当前状态，避免积压任务重复执行。AI 不可用时保留既有结果并标明状态。
6. **数据可迁出**：用户可以导出自建项目、任务和已确认记忆。删除或修改记忆后，后续个性化分析使用更新后的状态；历史记录和备份的处理范围需要明确说明。

7. **公开源码不泄露隐私**：公开候选文件、提交元数据、演示素材和构建测试输出均经过审查；真实个人及金融数据不进入公开仓库、日志或制品，旧仓库与历史数据保持私有。

### 第一版验收场景

| 场景 | 应能观察到的结果 |
| --- | --- |
| 打开每日简报 | 看到各领域摘要、数据时间和需处理事项，可以继续追问 |
| 邮件中出现截止事项 | 进入待整理收件箱，能核对原文明确的日期；推测截止时间与建议处理日期分别标明，未经确认不成为正式承诺 |
| 拆解一个学习或家庭项目 | 用户确认采纳任务与项目归属后跟踪进度；每日安排由系统提出建议，调整已确认的安排另需用户确认 |
| 核对日计划 | 显示日历占用、已知任务耗时及冲突；缺估时或覆盖不全时不声称已验证可行；日历变化时保留草案并提示复核 |
| 重复同步或收到同线程新邮件 | 同一事项不重复生成任务，已读不等于已处理；新邮件独立判断，可关联已有任务，纠正处理状态不自动修改 Gmail |
| 邮件正文缓存到期 | 自取得起最多缓存 24 小时，查看不续期；到期不可用并清理、确有需要才重新授权检查后读取；本地/云端备份及普通日志不含正文缓存，任务和处理状态独立保留 |
| 来源变化或暂时不可访问 | 更新来源状态与影响，保留用户决定和自写内容；日历记录暂缺不等于取消，授权撤销仍阻断受限内容使用 |
| 确认邮件或日历操作 | 仅执行已确认范围内且与预览一致的动作；转发/附件/批量/删除邮件/会议邀请/重复事件修改等转回原工具；只读会议与重复事件仍参与冲突判断，未经确认不执行 |
| 新闻涉及持仓 | 在授权范围内关联分析，解释影响和依据，不触发交易 |
| 新闻重复、修正或撤回 | 重复报道合并但保留来源；转载不当作独立证实；相对上次成功更新的实质变化可见，失败不当作没有变化 |
| 系统判断更新并与个人观点分歧 | 系统自动展示新判断及证据，原个人观点不被覆盖；重要分歧仅站内提示，查看不等于采纳，重复检查不反复提示；用户明确确认后才保存个人观点，采纳不触发外部操作 |
| 回看长期研究判断 | 可核对判断版本、变化原因及必要证据；暂停或归档不删除历史，无变化检查不制造新判断；更正或撤回可见，私人证据仍按自身期限和权限清理 |
| 查看财务配置建议 | 区分账户类型和实际数据覆盖范围，说明所采用的个人目标与假设 |
| 账户缺失或收益数据不足 | 缺失账户仍列为覆盖缺口，部分结果不冒充全部；无法排除现金流等影响时不伪造收益或精确波动归因 |
| 金融历史到期清理 | 关键交易与成本记录保留；日内快照 30 天、每日明细 5 年，到期后分别保留所需日级与月级历史；月度结果保留来源时间和缺口，不通过分析副本保留已到期明细 |
| 跨领域请求涉及工作邮件正文 | 未获相应授权时，不使用正文或由正文派生的受限内容 |
| 系统发现新的个人偏好 | 先提出记忆建议，用户确认后保存，且可修改或删除 |
| 主机离线后恢复 | 显示中断与过期情况，补充更新，不重复执行已完成操作 |
| 查看一次后台运行 | 能看出实际输入范围、结果与缺口；运行成功不等于用户确认或任务完成，重试不无限叠加 |
| AI 后台不可用或未来更换 | 主机在线时既有数据与内部任务管理仍可用，AI 分析明确受阻；数据、权限和调度不依赖某个会话；无自动切换、增费或向未授权服务发送私人数据 |
| 需要新增费用或订阅额度不足 | 在站内说明影响和可选方案，不自行增加支出 |
| 私人云端备份与恢复 | 每小时本地备份并加密上传；小时版本 48 小时、每日版本 30 天；正常约 1 小时丢失容忍，失败/离线显示真实恢复点及缺口；密钥独立，恢复先只读核对，不自动重放操作或恢复已撤销权限 |
| 登录凭据失效与本地恢复 | 备用通行密钥可用于登录；全部失效时须通过受保护的主机本地流程恢复原身份，旧会话失效；内网访问不能绕过验证，恢复不扩大权限或自动恢复外部授权 |
| 手机外出访问 | 主机在线时能查看核心内容、简单确认和追问；主机离线时允许不可用 |
| 审查并公开新项目 | 公开内容仅为经过审查的通用材料及虚构数据；不携带旧提交历史或私人资料，构建测试不访问真实账户，实际工作站仍需私人访问与身份验证 |

## 11 后续扩展与明确排除

后续可考虑：银行接入、家人独立使用与有限共享、长期目标和定期复盘、更完整的手机体验，以及更具体的投资决策支持。是否加入、何时加入另行讨论。

Drive、Codex 项目观察和知识库暂不加入。既有长期记忆要求继续保留，不因引入来源关系或运行记录而扩展为笔记编辑器、研究知识库或跨模块全文搜索。

本次补充仅完善现有功能的行为与验收规则，不引入复杂自动排程、固定的邮件四分类流程、新闻事件手工拆分合并界面、完整多因素量化归因或独立运行管理控制台。若后续需要加入这些能力，应先讨论范围变化；旧版的界面模板、存储方案、工程进展和发布状态不自动继承。

第一版不接入公司账户，不发送站外提醒，不自动交易或转账，不支持电脑离线时继续访问，也不擅自保存推断出的长期记忆或新增付费服务。

第一版需求已确认，本轮需求梳理结束。已进入工程路线图规划；应用功能的实际开发尚未开始。
