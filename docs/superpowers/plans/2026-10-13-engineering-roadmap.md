# 个人工作站工程 Roadmap

日期：2026-10-13
状态：工程路线图；只有项目材料整理已经执行，应用功能尚未开发。阶段状态以验收证据为准。

**目标：** 交付以新闻、投资观察和长期研究为核心，并整合个人邮件、日程、项目与待办的私人工作站，覆盖第一版全部已确认需求。

**依据：** [需求文档](../../requirements.md)、[系统设计](../../system-design.md)、[C v2 原型](../../../prototypes/dist/observatory-v2/index.html)。发生冲突时，用户明确决定与已确认需求优先；原型未展示的功能不能被省略。

**架构方向：** 单主机模块化应用，Web/API 与持久 Worker 分进程；工作站拥有业务数据、权限、费用和调度，AI 仅处理已获准上下文。采用系统设计建议的 TypeScript、React、Node.js、SQLite 等路线，具体受支持版本及依赖在 M2 固定。第一版只启用一个经验证的 AI 后台，Codex 优先。

这是一份阶段级工程路线图，不是逐文件编码指令。执行某阶段前，依据这里的输入、交付物和验收用例拆成可评审的小任务；不用重新讨论已经确认的产品边界。本次不执行这些开发阶段，也不创建定时任务或接入真实账户。

## 1 交付原则与范围

- 新项目独立 Git 历史；旧代码按模块审查后选择性复用，不复制旧 `.git`、私人数据或历史验收结论。第一版不要求完整迁移旧业务数据。
- 先建立身份、权限、数据来源、版本与删除边界，再允许真实私人数据流入。安全能力随阶段交付，不能留到最后补装。
- 产品优先级：先打通“变化 → 来源 → 长期判断 → 关联标的”，再完善个人行动与邮件日历闭环。优先交付不等于缩小第一版范围。
- 金融始终只读；Gmail 与日历的具体外部操作逐项预览确认；系统分析、用户观点、任务采纳、日计划确认、外部执行分别管理。
- 云 AI 必须满足按领域授权、最少必要数据、不用于训练及留存要求；未通过准入时只用合成输入。不能把 API 政策直接套到订阅登录路线。
- 所有提醒只在站内；主机在线关页仍运行，主机离线可暂停，手机也允许暂时不可用。Tailscale 私人访问仍须应用登录。
- 未来家庭身份和指定共享从数据模型预留，第一版不交付多人协作界面。
- 任何新增费用、扩权或范围变化仍需用户确认；技术失败不能自动变更供应商、付费路线或降低隐私要求。
- 不加入银行、公司账户、Drive、知识库、Codex 项目观察、跨模块全文搜索、长期目标/复盘、复杂排程、交易执行、站外推送或离线手机应用。

主路径为 M0 → M1 → M2 → M3 → M4 → M5/M6 → M7 → M8 → M9 → M10。M5 与 M6 可在共享契约稳定后独立推进；资源有限时优先 M5。M9 的私网、备份和恢复基础可在 M2/M3 后提前实现，不能拖到积累真实数据后才考虑备份。真实外部写入的日常启用必须同时通过 M7 和 M9 的操作账本恢复验收。

每阶段按 **未开始 → 实施中 → 待验收 → 已验收** 记录；有真实接入阻碍则记为“受阻/部分通过”，列明受影响能力。此表不承诺未经估算的日历工期。M1 完成后，根据实际接入限制与可投入时间估算每阶段工作量，不能以赶时间为由跳过验收。

三个可见里程碑：

1. **研究体验可评估：M4。** 用合成数据或已获准公开来源验证新闻与研究体验；不代表投资和日常行动已完成。
2. **全业务流程可评估：M8。** 五入口连通；真实接入未过关的模块仍标受阻，不称第一版完成。
3. **可长期私人使用：M10。** 全范围验收、备份恢复和运行验证通过。

## 3 M0 — 项目与材料基线

**交付物**

- 独立本地目录和 Git 仓库；README、需求、系统设计、本路线图、材料清单、隐私边界和项目工作规则。
- C v2 为主的可预览演示原型，初版 A/B/C 留作参考；合成样例与实际业务数据明确分离。
- `.private/` 保存原始文档、冻结原型和截图，排除在 Git 之外；旧项目不修改。
- GitHub 先私有；未选择公开身份与许可证前不擅自发布，不启用消耗额度的 CI。

**验收**

- [ ] 远端仓库与本地独立 Git 历史匹配；提交内容没有旧 Git 历史、凭证、私人原始材料或数据库。
- [ ] 新仓库的文档与静态资源本地链接有效；原型仍能预览，演示状态测试通过。
- [ ] 原始存档与已保存快照核验一致；脱敏副本明确不是原始快照的逐字复制。
- [ ] 需求全部场景在第 15 节有对应阶段；未实现能力不写成已通过。

**公开门槛（独立于建仓验收）**：用户确定公开账号/署名、提交邮箱与许可证；审查全部提交、依赖许可、文件、示例、截图和 CI 输出；不连接私人主机或账户进行公开 CI。只公开代码和合成材料，工作站服务仍为私网。仓库处于私有状态期间，尚未实现通过公开仓库减少 Actions 私有额度消耗的目标。

## 4 M1 — 接入可行性与能力契约

**目的：** 尽早发现会改变设计或交付范围的限制。先做最小验证，不建设完整业务 UI，不把当前聊天中可用的工具视为新应用已获授权。

**工作包与交付物**

1. `docs/validation/integration-matrix.md`：逐服务记录用途、认证方式、必要 scope、账户/字段覆盖、分页/增量/撤销、时间语义、限流、费用及失败状态。
2. `docs/validation/ai-admission.md`：Codex 候选路线、已有订阅资格、后台运行与额度、不训练政策的适用依据及核对日期、实际账户设置、远端留存/删除、本地会话清理、工具隔离证据。
3. 私人验证记录保存在 Git 外；仓库只保留合成响应与去身份化结论。真实登录和写入验证仅在用户明确授权相应对象后执行。
4. Google 验证一个个人账户、所选日历、读写 scope 与来源结果核对；两券商分别核验普通/退休账户和可取得的持仓、现金、成本、历史。
5. 新闻/行情选择满足许可、来源质量、深度与费用要求的候选组合。公开来源也需遵守使用许可，不下载付费原文规避限制。

**验收**

- [ ] 每项能力有“已验证/不支持/未知/待授权”状态和可复查证据；模拟通过与真实验证分别记录。
- [ ] Codex 用合成输入完成调用、中断、重启及额度受阻验证；不能访问私人目录、账户凭证或不允许的工具。隐私未核验时私人输入被阻止。
- [ ] Robinhood 与 Schwab 分别有账户类型和字段矩阵；缺历史、未知覆盖不写成已连接完整资产。
- [ ] Google 的读取、发送与事件操作分别验证，不以读取成功证明写入可用。
- [ ] 新费用、隐私不满足或必需能力不可用有明确阻碍。若没有满足要求的路线，向用户提出具体替代方案或范围变更，未经决定不悄悄缩减第一版。

**退出条件：** 基础契约足以支持 M2；受阻模块可继续用合成数据开发，但相关真实启用与最终验收保持受阻。M1 必须在 M10 前关闭所有第一版必需能力的阻碍。

## 5 M2 — 身份、权限与数据基础

**交付物**

- 应用骨架与五入口路由；共享类型/输入校验；SQLite 迁移、事务、稳定 ID、版本冲突；数据库仅在本地磁盘，运行数据置于仓库外。
- 通行密钥、多个备用凭据、应用会话撤销、受保护主机本地恢复；固定 User ID，未来多用户所有权与指定共享结构。
- `owner / domain / visibility / purpose / source-dependency` 授权模型；区分读取、跨领域使用、云处理、外部写入和共享。Google 领域规则与未分类保守状态。
- 来源记录、用户决定、系统解释三层；覆盖、数据时间、检查时间、来源版本与派生关系。
- 数据分类及删除/撤销代际、短期正文独立缓存、日志脱敏、凭证库引用；本地一致性导出/恢复基础，供后续完整备份使用。
- 技术决策记录与锁文件；核心逻辑使用行为测试，不为纯文档或微小样式增加形式测试。

**验收**

- [ ] 第二个合成用户不能访问第一个用户的对象，包括猜测 ID、列表、导出、摘要和助手上下文；第一版不需家庭协作界面。
- [ ] 工作邮件正文未获单独跨域授权时，正文及受限派生摘要均不能跨域；未分类或冲突规则不扩大使用范围。
- [ ] 撤销/删除与运行并发时，迟到输出、缓存及在途作业不能恢复被撤销内容；共享任务不夹带私人来源。
- [ ] 两个客户端同时编辑产生明确版本冲突，保留用户输入；同步不能覆盖用户决定。
- [ ] 主凭据失效可用备用登录；全部失效须证明主机控制权后恢复原身份，旧会话失效；内网或 localhost 不绕过认证。
- [ ] 业务数据库/日志/导出不含凭证和收到的邮件正文缓存；密钥访问失败有可理解状态。迁移失败能保留或恢复之前业务数据。

**依赖产物：** 权限服务、来源/覆盖契约、版本化写入、删除屏障、会话、数据分类与凭证引用由后续模块共同使用，禁止各自复制一套逻辑。

## 6 M3 — 后台调度、隔离 AI 与费用控制

**交付物**

- 持久 Job/Run、租约、心跳、领取代际、逻辑时槽去重、有限重试、取消与 blocked 状态；交互优先，不重放错过的所有时槽。
- 应用独立 Scheduler 与 Worker；每天简报及周中 30–60 分钟跟踪的规则模型、手动刷新合并、IANA 时区和夏令时策略。
- 单一 `AgentRunner` 适配器、受限上下文组装、来源引用和结构校验；数据/记忆/作业不依赖某个模型会话。
- 逐服务费用授权、预留/核对和使用账本；实际、估算、未知费用分开，月度预测说明依据。
- 简明运行状态：触发、实际输入、开始/结束、成果、缺口与原因，不记录完整私人输入。

**验收**

- [ ] 关闭网页后作业继续；双 Worker 竞争、崩溃后重领只发布一次有效结果；旧租约返回不能写入。
- [ ] 手动刷新与定时重合不制造并发风暴；休眠跨过多个时槽后合并补查；夏令时重复/缺失时刻不重复运行同一逻辑任务。
- [ ] 断网、429、认证过期、额度不足、取消分别有状态；重试有界，AI 不可用时仍可看历史与管理内部任务。
- [ ] 恶意邮件/网页提示不能改变权限、工具、收件人或费用；模型不能直接写业务库、发送邮件或调用金融写工具。
- [ ] 所有私人 AI 派发经过 M1 准入和 M2 当前权限核验；政策失效暂停相关请求。仅传必要字段，不含完整账号等无关标识。
- [ ] 未授权付费服务在定时、手动和失败重试路径均被阻止；额度耗尽不自动切 API 或第二后台。
- [ ] 用合成替身检验适配器契约，证明上下文可由业务记录重建；不要求接入真实第二后台。

## 7 M4 — 新闻与长期研究闭环

**交付物**

- 新闻采集、来源/转载谱系、事件聚合、事实/推断/建议区分、来源冲突、更正和撤回传播。
- AI/科技每日详细分析；宏观、地缘政治、市场默认简览，涉及关注对象或重大变化时深入分析。
- 长期主题、系统判断版本、个人观点版本、验证问题/反证、主题与标的多对多关联、条件性影响与历史。
- 对照上次成功结果展示新变化；用户已读与系统更新基线独立。研究行动输出任务候选契约，M6 完成正式采纳流程。
- 研究判断与必要证据长期保存，默认不完整归档原文；来源限制与私人证据期限继续生效。

**验收**

- [ ] 使用至少三个合成主题（技术、宏观、地缘政治）演示判断维持、条件收窄和判断改变；每次变化可追到新事实及来源时间。
- [ ] 同一原始报道多次转载只算一个证据源；冲突并列说明；来源更正/撤回能改变后续相关分析的有效性。
- [ ] 无新内容不生成虚假新版本；检查失败/覆盖不足不能声称“无变化”或“判断已获维持”。
- [ ] 每主题显示未验证问题、缺少的证据、改变判断的条件，以及对多个关联标的的作用路径、条件、时间和未知。
- [ ] 系统自动更新不改写个人观点；查看、追问、已读都不算采纳；明确采纳绑定所见版本。重要分歧只在站内且去重。
- [ ] 暂停/归档停止跟踪而不删除历史；私人源到期/撤销后不能通过证据摘录继续越权读取；失效链接不声称能还原完整原文。
- [ ] 桌面与手机的新闻 → 主题 → 标的往返可用，不依赖装饰图片理解内容。

## 8 M5 — 只读投资、历史与金融分析

**交付物**

- 隔离金融凭证与精确工具白名单；Robinhood、Schwab 适配器和普通/退休预期账户清单。
- 原子账户快照、持仓/现金/成本、币种、行情/汇率/现金流来源与时间、覆盖及缺字段。
- 当前状态与可取得历史起步；关键交易/成本长期、日内 30 天、每日 5 年后月度长期，清理与降粒度可追溯。
- 持仓派生关注对象，用户自选关注标的，美股及大宗商品研究；新闻/主题关联。
- 可支持的收益与风险计算；目标、期限、承受能力和资金需求资料；资产分布、配置与再平衡解释，不生成具体标的交易指令或执行入口。

**验收**

- [ ] 所有金融写工具从网关拒绝，包括模型诱导、别名和新增未知工具；AI 无金融凭证。
- [ ] 两券商及预期普通/退休账户真实覆盖逐一验收；未接通、不支持、过期、缺字段、覆盖未知分别显示，不能移除失败账户掩饰总量。
- [ ] 多币种、快照时间差、现金/购买力/未结算资金不会重复相加；部分合计明确范围。
- [ ] 用已知答案样例验证存取款、分红费用、拆股/其他公司行动、价格与汇率变化；缺关键数据不绘制完整收益率或精确归因。
- [ ] 不要求完整历史回填或过去 5 年齐备；数据时间和缺口可见，当前快照不被转成虚构历史交易。
- [ ] 用可控时钟验证 30 天与 5 年边界、日/月保留和长期成本记录；重复同步不重置期限，分析副本不延长过期明细留存。
- [ ] 配置建议说明个人资料版本、账户类型、范围与假设；缺目标/期限等资料只给资料支持的结果，不推断完整家庭财务。

**真实启用门槛：** 只读账户同步与本地展示须通过 M1 券商验证、M2 权限/凭证/留存以及 M3 非 AI 调度与费用控制；不以 AI 可用为前提。将私人金融数据交给 AI 分析另须通过 M3 AI 准入。长期日常使用还须 M9 备份恢复通过。真实数据只在私人环境验证，公开测试为重新构造的合成数据。
